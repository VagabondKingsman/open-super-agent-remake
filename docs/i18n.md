# Dịch giao diện VI / EN / ZH trên v0.6

Bản remake v0.6 dùng kiến trúc Chinese-as-key của upstream. Không còn i18next/react-i18next hay các gói `common.json`, prompt/schema/catalog locale kiểu v0.5.

## Nguồn dịch

| Phần | Nguồn |
|---|---|
| UI | `web/src/i18n.ts`, `web/src/locales/en.json`, `vi.json` |
| Lỗi API / thông báo / kênh chat | `osa/i18n.py`, `osa/locales/en.json`, `vi.json` |
| Tiếng Trung | Chính chuỗi gốc làm khóa, không cần zh.json |
| Model | Prompt nội bộ upstream, thêm chỉ dẫn trả lời theo ngôn ngữ UI |
| Metadata ứng dụng / mẫu Bot | English upstream trong chế độ VI nếu có |

Ví dụ `t('保存')` trả `Lưu` khi VI, `Save` khi EN, `保存` khi ZH. Dùng `{name}` cho biến; `tc` thêm ngữ cảnh `context::中文`, `tn` cho phần tử React. VI không cần hai dạng số ít/số nhiều, nên dùng chuỗi chứa `{n}`.

Các giá trị VI phải khớp bộ khóa EN và giữ tên placeholder. Bot, Computer, Docker, MCP, API, webhook là thuật ngữ giữ nguyên khi phù hợp. Không dịch ID công cụ, marker giao thức, dữ liệu người dùng hay regex tương thích.

## Mặc định, phát hiện và di chuyển lựa chọn

- Chưa lưu ngôn ngữ: mặc định VI, không phụ thuộc browser.
- Hàm phát hiện nhận `vi*` → vi, `zh*` → zh, còn lại en. Không dùng phát hiện để đổi ngầm mặc định VI.
- Frontend ưu tiên localStorage `osa.lang` hợp lệ; nếu chưa có thì chuyển `osa.locale` cũ hợp lệ một lần, xóa khóa cũ. Locale định dạng là `vi-VN`, `en-US`, `zh-CN`.
- Service worker không đọc được localStorage. Chrome cũng không đưa header Cookie vào fetch của worker. Mỗi lần mở trang, client ghi ngôn ngữ UI vào Cache Storage `osa-lang`, khóa `/osa-lang`, giá trị `vi`, `en` hoặc `zh`. Đây không phải secret. Khi máy chủ không trả trang, worker đọc cache: `vi` hiện tiếng Việt rồi tiếng Anh, `en` chỉ tiếng Anh, `zh` tiếng Trung rồi tiếng Anh. Thiếu cache hoặc giá trị lạ thì dùng tiếng Việt. Không lấy `navigator.language`, vì cài mới vẫn mặc định tiếng Việt.
- Server lưu `settings.language`. Nếu chưa có, chuyển `overrides.locale` hợp lệ của remake cũ một lần. Bootstrap đầu tiên nhận preference của client; khi server đã lưu thì dùng lựa chọn server làm chuẩn chung.
- Chọn ngôn ngữ trong Settings/onboarding gửi `PUT /api/settings {"language":"vi"}`; client lưu `osa.lang` rồi tải lại. Các nhãn tính lúc import cũng đổi cùng lần tải.
- `OSA_LOCALE` của v0.5 không còn dùng. Đổi trong UI thay vì sửa biến môi trường.

## Kiểm tra

```bash
uv run python -m osa.i18n
uv run pytest -q
(cd web && npm test && npm run build)
```

Checker chạy cho cả EN và VI: khóa thiếu, placeholder sai, chuỗi rỗng, ký tự Hán trong giá trị dịch và chữ Trung chưa bọc trên frontend. Các trường hợp cố ý giữ tiếng Trung trong mã cần `i18n-ignore` có lý do, không dùng để che nhãn chưa dịch.

Node tests thực thi module i18n đã biên dịch trong môi trường trình duyệt giả: mặc định, migration, preference, phát hiện và đồng bộ. Pytest dùng database tạm để kiểm tra locale server, API, Worker ba ngôn ngữ và thiếu Docker. Dịch đúng khóa không chứng minh mọi tích hợp ngoài đã chạy.
